Flash the Watch

Your pet lives in a browser. What does it take to move it into a device you can wear?

What's the difference between code that runs in a browser and code that runs in a watch?

Your pet has been living in a browser tab. The browser is doing a lot of invisible work for you — it handles the screen, the touch events, the memory. It's a translator between your code and the hardware.

When you program a microcontroller directly, you remove the translator. You talk to the hardware yourself.

What is a microcontroller?

A microcontroller is a tiny computer on a single chip — processor, memory, and connections to hardware all in one. The watch uses an ESP32-S3: fast enough to run a game, small enough to fit in a wristband, cheap enough to put in a classroom project.

Unlike your laptop, a microcontroller has no operating system. When it turns on, it runs one program — your program — in a loop, forever. There is no file system to open, no browser to launch. Just:

setup(); // runs once when the watch turns on while (true) { loop(); // runs forever, as fast as the chip allows }

Two languages, one idea

The pet's logic — what makes it hungry, what makes it happy — doesn't change when you move to hardware. The language does.

JavaScript (browser)
let food = 80; function feed() { food = Math.min( 100, food + 20 ); draw(); }
C++ (watch)
int food = 80; void feed() { food = min( 100, food + 20 ); draw(); }

Same logic, same function name, same min(). The differences: let becomes int (you declare the type), function becomes void (you declare what the function returns). The thinking is identical.

Why declare the type? JavaScript figures out at runtime whether food is a number or a string. C++ needs to know at compile time — before the code ever runs — because it's being translated directly into machine instructions. Knowing the type makes that translation possible.

The display: talking to hardware directly

In a browser, you draw with canvas.fillRect() and the browser handles everything between your code and the screen. On the watch, you talk to the display chip directly via a library that handles the low-level protocol.

// Browser (JavaScript): ctx.fillStyle = '#6c63ff'; ctx.fillRect(10, 10, 50, 50); // Watch (C++ with Arduino_GFX_Library): gfx->fillScreen(BLACK); gfx->fillCircle(60, 60, 30, gfx->color565(108, 99, 255));

The drawing calls are different, but the concept — tell the screen where and what color — is the same.

Pin numbers: where things are connected

Every wire going into a microcontroller connects to a numbered pin. The display connects to pins 10, 11, 12, 13, 14. The touch sensor connects to pins 8 and 9. Your code has to know those numbers — if you get one wrong, the screen won't initialize, and nothing will work.

// These must match the actual hardware wiring: #define LCD_CS 10 #define LCD_SCK 12 #define LCD_D0 11 #define TOUCH_SDA 8 #define TOUCH_SCL 9
Verify before you build. Pin numbers vary between hardware revisions. Always check them against the manufacturer's documentation for your specific board before uploading. Wrong pins mean a blank screen — no damage, but nothing works until you fix it.

Uploading: from code to chip

When you click Upload in Arduino IDE, four things happen:

  • Compile — your C++ is translated into machine instructions the ESP32-S3 can run
  • Link — the compiler adds library code (like the display driver) to your program
  • Transfer — the compiled binary is sent over USB to the watch's flash memory
  • Reset — the watch reboots and runs your program from the beginning

The whole process takes 10–30 seconds. When it's done, the watch runs your code — not inside a browser, not in a simulator, on the actual hardware.
