What happens to your pet when you close the tab?

Your pet's stats — food, happy, energy — live in the computer's memory while the page is open. Memory is fast. But it has one serious problem: when the tab closes, it's gone. Everything resets to zero. Your pet forgets it ever existed.

Today you'll learn how to rescue your pet from this fate by writing its stats to a place that actually sticks around.

Memory vs. persistent storage

Here's the difference:

  • Memory (RAM) — blazing fast, but wiped when the page closes. Variables live here.
  • Persistent storage — written to disk. Survives tab closes, browser restarts, and reboots. Much slower to read and write, but the data stays put.

Your browser gives every webpage a small built-in notebook called localStorage. It's persistent storage you can reach with two simple functions.

localStorage survives tab closes, browser restarts, and reboots. It's not in memory — it's written to disk. The data will still be there a week from now.

setItem and getItem — the browser's notebook

You write to localStorage with setItem and read it back with getItem. Both take a key — like a label on a jar — and setItem takes a value too.

// Write a value
localStorage.setItem('petFood', '80');

// Read it back later (even after a page reload)
const saved = localStorage.getItem('petFood');
console.log(saved); // '80' ← notice: a string, not a number

Why values must be strings

localStorage can only store text. It doesn't know about numbers, booleans, or objects — everything goes in as a string and comes back as a string. This causes a trap that catches almost everyone the first time.

'80' and 80 look the same but aren't.
'80' + 20 = '8020' — JavaScript sees two strings and glues them together.
parseFloat('80') + 20 = 100 — converting first gives you real math.
Always convert back after reading from localStorage.

The fix is parseFloat (or parseInt for whole numbers). Call it immediately after getItem so the rest of your code never sees a string where it expects a number.

// Save a number
localStorage.setItem('petFood', 80);

// Load it back as a real number
const food = parseFloat(localStorage.getItem('petFood'));
food + 20; // 100 ✓ — actual addition, not string glue

Saving and loading a full pet — JSON

Your pet has three stats. You could save each one separately with its own key. That works, but it's messy — three separate saves, three separate loads, three places to forget one.

A cleaner approach: bundle the whole pet into a single object, then convert it to a string with JSON.stringify, and convert it back with JSON.parse.

// Bundle the stats into one object and stringify it
function save() {
  const data = { food: pet.food, happy: pet.happy, energy: pet.energy };
  localStorage.setItem('lesson-pet-stats', JSON.stringify(data));
}

// Read the string back and parse it into a real object
function load() {
  const raw = localStorage.getItem('lesson-pet-stats');
  if (!raw) return; // nothing saved yet — bail out
  const data = JSON.parse(raw);
  pet.food = parseFloat(data.food);
  pet.happy = parseFloat(data.happy);
  pet.energy = parseFloat(data.energy);
}

JSON.stringify turns { food: 80, happy: 70, energy: 50 } into the string '{"food":80,"happy":70,"energy":50}'. JSON.parse does the reverse. The numbers stay numbers — no parseFloat needed this time, because JSON knows about number types. But it doesn't hurt to use parseFloat anyway as a safety net.

When to save

You have two choices — and most real games use both at once:

  • On every action — call save() immediately when the player feeds, plays, or rests. No data is ever more than one action old.
  • On a timer — use setInterval(save, 10000) to save every 10 seconds automatically, even if the player just watches.
// Auto-save every 10 seconds
setInterval(save, 10000);

// Also save immediately on any action
function feed() {
  pet.food = Math.min(100, pet.food + 20);
  save(); // right here — don't wait for the interval
}
